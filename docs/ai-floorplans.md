## 고객 흐름

1. `/spaces/recognize`: JPG·PNG·WEBP 또는 PDF를 선택한다. PDF는 분석할 페이지를 고르고 브라우저에서 이미지로 바꾼다. 10MB 원본, 최대 3,000px·8MB PNG 분석 입력.
2. 사용자가 도면 이미지의 OpenAI 분석 전송에 동의하면 로그인한 고객의 서버가 Responses API로 보낸다. 키가 없으면 분석을 하지 않고 수동 경로를 안내한다. 가짜 인식 결과나 면적에서 가정한 구조를 반환하지 않는다.
3. AI가 구조의 종류를 읽으면 서버에서 원본 이미지의 벽선과 문·창 틈으로 좌표를 다시 측정한다. 바깥·내부 벽, 문·창, 방 이름을 원본에 겹쳐 확인한다. 좌표는 이미지의 비율이며 실제 길이를 임의로 추정하지 않는다. 읽힌 전체 가로 숫자가 있더라도 고객이 확인해야 한다. 가로를 확인하면 원본 종횡비로 동일 축척을 적용한다. 천장 높이·벽 두께·문 방향은 편집 시작값으로 표시한다.
4. 고객이 치수와 구조를 확인한 뒤 내 공간에 저장한다. 기존 가구·상품 배치, 3D, 시공 제안 요청에 연결한다. 공사 요청을 자동으로 보내지 않는다. 기존 주거 프로젝트에도 가져올 수 있지만 이미 있는 평면을 덮어쓰지 않는다.
5. 저장할 때 서버의 소유자별 인식 기록을 다시 읽어 평면을 만든다. 클라이언트가 보낸 임의 벽 데이터는 사용하지 않는다. 같은 인식 기록은 한 프로젝트에 한 번만 연결한다. 요청 뒤 편집한 것은 기존처럼 변경 내용 보내기 전에는 업체에 반영하지 않는다.

주거 평면이 이번 AI 인식 대상이다. 사무실은 기존 치수 입력·도면 따라 그리기·자동 배치를 계속 사용한다. 집의 가구 자동 배치, 사선·곡선 벽, 여러 층, 구조·설비·법규 판정은 지원하지 않는다. 잘못 연결된 문이나 기운 벽, 겹침 등 저장할 수 없는 인식 결과는 직접 입력 경로를 안내한다.

## 주소에서 시작

`/spaces/address`는 기존 주소/건축물대장 경로와 등록 도면 검색을 연결한다. `/spaces/templates`에서 실제로 등록한 주소·단지명·타입만 검색한다. 같은 주소나 전용면적만으로 평면을 추측하거나 자동으로 한 타입을 선택하지 않는다. 등록 도면이 없으면 도면 업로드로 안내한다.

운영자는 `/admin/floorplans`에서 사용 권한과 개인정보 제외를 확인한 주거 프로젝트의 평면을 등록한다. 공개 복사본에는 구조·문·창·방·고정 구조물만 들어가고 원본 고객의 밑그림·가구·요청 내용은 제외한다. 고객은 평면·3D를 보고 타입을 직접 확인한 뒤 독립 복사본을 만든다. 운영자가 원본을 숨겨도 이미 만든 고객 공간은 유지된다. 운영자가 등록한 사용 허가·실측 도면은 아직 없다. 공개 자료 기반 참고 도면은 아래 별도 범위다.

## 연결과 운영

- 설정 예시: `config/environment.example` → 로컬 `.env.local` 또는 Docker `.env`.
- `OPENAI_API_KEY`: 서버 전용. 브라우저 응답·콘솔·Git에 포함하지 않는다.
- `OPENAI_FLOORPLAN_MODEL`: 선택, 기본 `gpt-5.4-2026-03-05`. 이미지 입력과 strict Structured Outputs 지원 모델이어야 한다. GPT-5/6 계열에는 추론 `medium`, 원본 입력을 지원하는 모델에는 `detail:original`을 사용한다. 이전 모델에는 지원하지 않는 옵션을 보내지 않는다.
- Responses API `store:false`, 이미지 입력, JSON Schema strict 출력. 거절·미완료·잘못된 JSON·키 오류·429·타임아웃을 안내한다. `store:false`는 OpenAI의 모든 보관 정책을 대신 설명하는 의미가 아니다.
- 고객별 동시 분석 한 건, 24시간 30회. API 요청 제한 시간은 4분이며, 끊긴 분석은 5분 초과 뒤 다시 시도할 수 있다. 결과는 1일 동안 가져올 수 있다. 이 만료는 파일 삭제 정책이 아니며 도면·기록 삭제 요청은 운영자가 처리한다.
- `floorplan_jobs`, `floorplan_templates`, `floorplan_selections`를 추가하며 기존 행이나 표의 값을 바꾸지 않는다. 기존 백업 명령에 함께 포함된다.
- 고객 도면은 비공개다. 내 계정 외 조회·가져오기를 막고, 업체에는 고객이 요청으로 전달한 해당 버전만 보인다. 출처와 업체 확인 전 안내는 고객·운영자·업체·인쇄에 유지된다.

이전 실제 검증에서 발견한 창·현관 위치 오류와 ㄱ자 내부 벽 연결 오류를 `lib/floorplan/refine.ts`에서 보완했다. AI 응답을 그대로 확정하지 않고 원본 픽셀의 구조선을 찾아 외곽 안쪽 면·내부 벽·개구부 끝을 측정한다. 같은 선의 벽 조각은 합치고, 실제로 닿는 내부 벽만 접합한다. 실제로 떨어진 벽을 가까운 다른 벽에 붙이지 않는다. 누락한 문·창이나 원본에 없는 개구부, 모호한 선은 성공 결과로 내놓지 않는다. 모델·정답 좌표·파일 이름별 특례나 정답 전달은 사용하지 않는다.

## 최초 실제 API 검증 — 수정 전 기록 (2026-10-05)

사용자가 제공한 키로 OpenAI API를 실제 호출했다. 키는 `.env.local`에만 저장했고 Git과 브라우저에 포함하지 않았다. 기존 3100·3330 대신 격리 데이터와 3342 서버에서 검사했다. 검증 도면은 정답 좌표를 아는 **가상 주거 도면**이며 실제 고객/아파트 도면이 아니다. 정답 좌표는 모델에 전달하지 않았다. 최초 실패부터 기록을 보관했으며 실패한 결과를 고정 성공 결과로 대체하지 않았다.

- GPT-4.1 최초 3회: 벽·문을 잘못 읽어 모두 평면 변환 검사에서 거부됐다. 모델을 GPT-5.4로 변경하고 문짝·열림 호 제외, 개구부를 벽 위로 표시, 내부 벽과 외곽 구분, 전체 픽셀 좌표 안내, 중간 추론을 적용했다.
- 실제 API 호출 총 9회: 모델·지침 비교 7회와 서비스 브라우저 흐름 2회. 최종 브라우저는 인식 → 실제 3D → 저장·가구 수정 → 원본 비공개 → 요청 기록 고정 → 운영자 배정 → 업체 전달 → 휴대폰·인쇄 → 3D 사진 거부를 확인했다. **18개 통과·정확도 1개 실패**다.
- 최종 3실 도면: 내부 벽 2개, 문·창 5개, 방 이름 3개와 전체 가로 10,000mm는 읽었다. 외곽·내부 벽 좌표는 정답과 같지만 왼쪽 창 끝점이 100px(1,000mm) 길게 잡혔고 현관 시작점도 300mm 어긋났다. 개수 일치를 위치 정확도로 해석하지 않는다.
- 최종 ㄱ자 도면: 외곽·벽·문·창 위치 최대 약 128mm 차이. 내부 벽과 외곽 모서리가 약 80mm 어긋나 두 방이 하나로 계산됐다. 초기 다른 호출에서는 같은 도면이 두 방으로 나왔으므로 응답 변동도 있다.
- 실제 응답을 재생한 수정 검사 **12/12**: 창 폭 3,500→2,500mm와 현관 위치·폭을 편집·저장하고 새 요청으로 업체에 전달했다. ㄱ자 벽을 모서리에 연결하면 두 방으로 복원되고 저장·다시 열기에 유지됐다. 이 검사는 추가 유료 호출을 하지 않았으며 모델 정확도 통과로 계산하지 않는다.
