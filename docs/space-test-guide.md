# 고객 테스트 준비: 필요한 도면·치수 자료와 참여 조건

이번 테스트로 확인할 것은 두 가지입니다.

1. **흐름이 실제로 이어지는가**: 내 공간 만들기(치수 입력 또는 도면 따라 그리기) → 가구 배치 수정 → 저장 → 원할 때 시공 제안 요청 → 업체별 제안 비교.
2. **실제 공간과 맞는가**: 고객이 만든 공간이 실측과 얼마나 맞는지, 업체가 받은 배치만으로 견적을 낼 수 있는지. 차이는 **프로그램이 만든 차이**와 **사람이 재거나 찍을 때 생긴 차이**로 나눠 기록합니다(5장).

참여 인원은 아직 정하지 않았습니다. 아래 조건은 인원이 정해지면 그대로 모집 안내에 쓸 수 있게 정리했습니다.

## 1. 고객 참여 조건

| 조건 | 이유 |
| --- | --- |
| 20~50평 사무실 | 자동 배치가 출발점을 만드는 범위입니다. 그 밖의 크기도 빈 공간에서 직접 놓을 수는 있습니다. |
| 직사각형, 또는 도면이 있는 ㄱ자·꺾인 공간 | 직사각형은 치수만으로 만들고 자동 배치에서 시작합니다. 꺾인 공간은 도면을 따라 그려(PC) 실제 모양대로 만들고, 자동 배치 없이 빈 공간에서 가구를 놓습니다. 기울어진 벽·곡선 벽은 아직 그리지 못합니다. |
| 실제로 이전·인테리어를 검토 중 | 실제 업체 제안까지 이어지는지 봐야 해서, 공사 계획이 있는 곳이 좋습니다. |
| 현장에 들어가 치수를 잴 수 있음 | 입력한 치수와 실측을 비교해야 합니다. |
| PC와 휴대폰을 모두 써 볼 수 있음 | 휴대폰 편집(가구 추가·고르기·이동·회전·되돌리기)을 꼭 확인해야 합니다. 1명 이상은 휴대폰만으로 진행해 보기를 권합니다. 도면 따라 그리기는 PC로 합니다. |
| 개인정보 수집·이용 동의 | 가입할 때 받습니다. 운영자는 테스트 요청을 ‘테스트’로 표시해 실제 요청과 나눠 봅니다. |

공간 구성을 섞어 모으면 좋습니다: **도면이 있는 곳**(따라 그리기), 치수만 아는 곳, **ㄱ자 등 꺾인 곳**, **기둥이 있는 곳**, **출입문이 벽 가운데에 있는 곳**(자동 배치 없이 빈 공간에서 시작하는 흐름 확인), 창이 옆 벽에 있는 곳, **급배수 위치를 아는 곳**(탕비 설비 확인 흐름).

## 2. 업체 참여 조건

- 2~3곳. 소형 사무실 견적 경험이 있는 곳.
- 고객이 보낸 배치(평면·3D)와 조건만으로 1차 견적을 내 보고, 설계 제안(‘고객 배치대로’ 또는 ‘수정 제안’ + 첨부)을 작성해 줄 수 있는 곳.
- 현장 방문 뒤 견적이 얼마나 바뀌었는지 알려 줄 수 있는 곳.

## 3. 공간마다 받아 둘 자료

| 구분 | 자료 | 비고 |
| --- | --- | --- |
| 필수 | 실내 가로(출입문 벽)·세로, mm — 또는 도면 | 벽면 사이 거리. 세로는 두세 곳을 재서 가장 짧은 값. 도면이 있으면 따라 그리기로 대신할 수 있습니다 |
| 필수 | 출입문: 가까운 모서리에서 문틀 가장자리까지, 문 폭 | |
| 필수 | 직원 좌석 수, 필요한 방(대표실·회의실 인원·탕비실·창고) | |
| 있으면 | 도면 파일(PDF·JPG·PNG) | 따라 그리기 밑그림으로 씁니다. 치수를 자동으로 읽지 않습니다. DWG·DXF는 PDF나 이미지로 내보내 주세요. 도면에 **숫자로 적힌 치수가 하나 이상** 있어야 축척을 맞출 수 있습니다 |
| 있으면 | 창: 벽별 위치와 폭 | 모르면 ‘잘 모름’ — 창을 가정하지 않습니다 |
| 있으면 | 기둥: 왼쪽 벽·출입문 벽에서 모서리까지, 가로·세로 | |
| 있으면 | 급배수 위치(싱크대를 연결할 물 공급·배수) | 고객이 현장에서 직접 확인한 경우만(‘고객 확인’으로 표시). 모르면 탕비 설비는 ‘자동 제안 위치’로 남고 업체가 확인합니다 |
| 있으면 | 천장 높이, 계약서상 전용면적(평) | 전용면적은 계산 면적 옆에 숫자(차이 ㎡·%)로 보여 줄 뿐, 맞는지 판정하지 않습니다 |
| 있으면 | 현장 사진 4~8장 | 네 모서리, 출입문, 창, 천장·설비(분전반·급배수·냉난방기) |
| 대조용 | 실측값(레이저 거리계) | 운영자가 따로 재서 입력값과 비교합니다. 고객에게는 보이지 않습니다 |

치수 재는 법은 서비스의 이용 방법(`/guide#measure`)에도 있습니다.

## 4. 고객 과제(순서대로)

1. 가진 자료로 **내 공간 만들기**. 치수만 있으면 치수 입력, 도면이 있으면 **도면 따라 그리기(PC)**: 도면 올리기 → 축척 맞추기 → 벽 모서리 찍기 → 출입문·창·기둥·급배수 놓기 → 벽 길이를 도면 숫자로 맞추기. (도움 없이 끝내는지, 어디서 멈추는지 기록)
2. 자동 배치(또는 빈 공간)에서 **가구를 추가하고, 두 개를 옮기고 하나를 돌린 뒤 저장**. 다시 열어 그대로인지 확인.
3. **휴대폰에서** 평면 아래 ‘가구 추가’로 하나 놓고, 눌러 고르고, 화살표로 옮기고, 돌리고, 되돌리기. 접힌 ‘자동 검사’를 펼쳐 보기.
4. 탕비 설비를 눌러 ‘자동 제안 위치’인지 확인하고, 급배수 위치를 알면 옮긴 뒤 **‘이 자리가 실제 설비 위치예요’**로 확인.
5. 저장한 버전 가운데 하나를 골라 **시공 제안 요청**. (요청하지 않고 멈춰도 됩니다 — 선택적 이용 확인)
6. 요청 뒤 배치를 하나 고쳐 저장하고, 같은 업체에 **변경 내용 보내기**.
7. 도착한 제안을 **같은 요청 기준끼리 비교**하고 현장 방문 요청.

## 5. 기록할 것

### 5-1. 치수 정확도: 세 가지 차이를 나눠 기록

예전 기준 ‘입력 치수와 실측 차이 2% 이내’는 프로그램의 정확도와 사람이 잰 값의 차이를 한데 묶은 것이라 아래처럼 나눕니다.

| 구분 | 무엇과 무엇의 차이 | 누가 확인 | 기준 |
| --- | --- | --- | --- |
| **프로그램 치수 정확도** | 고객이 넣은 숫자(또는 도면 숫자로 맞춘 벽 길이) ↔ 저장·평면도·3D·검사·업체 화면에 쓰인 값 | 자동 테스트(테스트 전에 끝냄) | **차이 없음**. 1mm 단위로 저장합니다. 테스트 모임에서는 다시 재지 않습니다 |
| 따라 그리기 찍기 차이 | 도면에 적힌 치수 ↔ 화면에서 찍어 생긴 길이 | 고객 화면(벽 N · 길이 표시) | 참고: 전체 보기에서 화면 1칸이 도면 약 10mm라 ±20mm 안팎이 생깁니다. 확대해 찍거나 ‘벽 길이를 도면 숫자로 맞추기’로 고치면 도면 숫자와 같아집니다. 벽 하나를 고치면 다음 벽이 밀리고 그다음 벽 길이가 바뀌며, 화면에 강조·전후 값·되돌리기가 나옵니다 |
| **사용자 측정 오차** | 고객이 넣은 값(또는 도면 숫자) ↔ 운영자 레이저 실측 | 운영자, 공간마다 벽별로 | 참고값 **2% 이내**(11m에서 약 22cm) — 합격·불합격 기준이 아니라 참고값이며 확정 전입니다. 넘으면 원인을 적습니다: 잰 위치(걸레받이·몰딩), 벽 마감 두께, 도면과 현장이 다름, 잘못 넣은 숫자 |

프로그램 치수 정확도는 자동 테스트로 확인합니다.

- `npm run check:space`: 서로 다른 치수의 공간이 그 치수대로 바닥·벽·출입문·창·기둥·급배수를 만드는지, 따라 그린 꼭짓점·축척·회전·벽 길이 맞추기가 값을 바꾸지 않는지 봅니다(130개).
- 화면 테스트(e2e9): 테스트 도면(1px = 10mm)에서 축척을 맞추고 따라 그린 뒤 도면 숫자로 맞추면 벽 길이가 정확히 5,000·3,000·3,000·4,000·8,000·7,000mm, 면적 47.0㎡로 저장되는지 봅니다.

사용자 측정 오차는 이렇게 적습니다.

| 공간 | 벽 | 고객 입력(mm) | 레이저 실측(mm) | 차이(mm) | 차이(%) | 원인 메모 |
| --- | --- | --- | --- | --- | --- | --- |
| 예) A | 가로(출입문 벽) | 11,000 | 10,940 | +60 | 0.5% | 걸레받이 위에서 잼 |

도면으로 만든 공간은 ‘도면 숫자 ↔ 실측’을 같은 표에 적고, 원인 메모에 ‘도면’이라고 남깁니다. 도면 자체가 현장과 다른 경우를 따로 셀 수 있게 하기 위해서입니다.

### 5-2. 흐름과 판단

| 항목 | 기준(제안, 확정 아님) |
| --- | --- |
| 과제별 완료 여부·막힌 곳·걸린 시간 | 1~4번은 도움 없이 끝내기. 도면 따라 그리기는 축척·닫기·출입문 단계에서 멈추는지 따로 기록 |
| 휴대폰에서 가구 추가·편집 버튼을 찾는 데 걸린 시간 | 평면 아래 ‘가구 추가’와 아래쪽 조작판을 안내 없이 찾는지 |
| 자동 검사 경고와 실제 문제의 일치 | 문 앞 750mm는 **현재 임시 검사값**, 탕비 설비와 급배수 직선 3,000mm는 **현재 임시 알림값**입니다. 현장 감각과 맞는지 업체 의견(값마다 따로 조정하며, 다른 기능 개발의 선행조건이 아닙니다) |
| 탕비 설비 자동 제안 위치와 실제 급배수 위치 | 자동 제안 위치가 실제와 얼마나 달랐는지, 업체가 배관 연장을 언급했는지 |
| 업체의 추가 질문·자료 요청 건수 | 배치만으로 견적이 가능한지. 꺾인 공간(따라 그린 모양)도 같은지 |
| 현장 방문 뒤 견적 변화 | 배치 기준 견적의 정확도 |
| 요청 없이 공간만 만든 사람이 있는지 | 선택적 이용이 실제로 쓰이는지 |

서비스 기록(`events`)에도 공간 만들기(도면 따라 그리기 여부 포함), 배치 저장, 요청, 변경 내용 보내기가 남습니다.

## 6. 참여자에게 미리 알릴 것

- 치수 입력은 직사각형만 만듭니다. ㄱ자 등 꺾인 공간은 도면 따라 그리기(PC)로 실제 모양대로 만들고, 자동 배치 없이 빈 공간에서 가구를 놓습니다. 다른 모양을 직사각형으로 바꾸지 않습니다.
- 도면 따라 그리기는 도면을 자동으로 읽지 않습니다. 축척을 맞추고 벽 모서리를 직접 찍습니다. 직각으로 만나는 벽만 그릴 수 있습니다.
- 자동 배치는 출입문이 가까운 모서리에서 2,500mm 안에 있을 때만 만듭니다(**현재 자동 배치 지원 범위**). 벗어나면 빈 공간에서 시작합니다.
- 칸막이·방 크기는 아직 직접 바꿀 수 없습니다(가구만). 자동 배치는 기둥을 피하지 않으며, 겹치면 검사에서 알려 줍니다.
- 탕비 설비는 자동 배치가 정한 **자동 제안 위치**이며 급배수를 확인한 위치가 아닙니다. 실제 위치를 알면 옮긴 뒤 ‘고객 확인’으로 표시해 주세요. 고객 확인은 업체 확인이 아니며, 업체가 현장에서 다시 확인합니다.
- 급배수와 탕비 설비 사이 3,000mm는 **현재 임시 알림 거리**입니다. 멀면 거리만 알리고, 배관 연결이 되는지는 판정하지 않습니다.
- 지금 공간 입력이 재현하는 것은 **실내 외곽 형태와 출입문·창·기둥**입니다. 도면에 방이 나뉘어 있어도 공간 안의 벽·방문(아파트·주택의 방 구조)은 그리지 않습니다(후속 범위).
- 자동 검사에 걸린 곳이 없어도 시공할 수 있다는 뜻은 아닙니다. 현장 실측과 업체 확인이 필요합니다.
- 상세 주소와 연락처는 고객이 현장 방문을 요청한 업체에만 공개됩니다. 업체끼리는 서로의 금액과 제안을 볼 수 없습니다.
- 테스트 자료의 보관 기간은 개인정보 처리방침에서 확정해야 합니다(지금 초안의 ‘요청 종료 후 1년’은 자리표시).

## 7. 운영 준비(테스트 전에)

- 배포 전 대면 테스트는 이 컴퓨터에서 운영용으로 띄웁니다(`npm run serve:start`, README ‘로컬 운영용 실행’). 테스트 시작 전에 `npm run data:backup -- before-test`로 백업합니다. 테스트 기간에는 데이터를 초기화하지 않습니다.
- 실제 업체는 운영자 화면 → 업체 → ‘업체 직접 등록’으로 만들고, ‘메일 발송 기록’에 보이는 비밀번호 설정 링크를 업체에게 직접 열어 줍니다. 배정할 때는 ‘실제 업체’ 묶음에서 고릅니다(‘예시 업체’는 시연용이라 응답하지 않음).

- 서버·도메인·메일 발송 계정이 정해지면 배포(DEPLOY.md). 참여자가 쓸 주소가 필요합니다.
- 참여 업체 계정 등록(운영자 화면 → 업체 직접 등록) 또는 입점 신청 승인.
- 참여자 요청은 운영자 화면에서 ‘테스트 요청으로 표시’.
- 실측 대조용 레이저 거리계와 5-1의 기록 표.

## 8. 도면 따라 그리기 소규모 테스트(실제 도면을 가진 고객)

목적: 실제 도면을 가진 고객이 **도움 없이 어디까지 할 수 있는지**. 운영자는 옆에서 보기만 하고, 멈추면 1분 기다린 뒤 멈춘 단계를 기록하고 나서 도와줍니다.

준비: PC(마우스 권장), 고객이 가진 도면 원본(PDF·이미지, 종이 도면이면 반듯하게 스캔·촬영), 계약서상 전용면적, 대조용 레이저 거리계.

| 단계 | 끝났다고 볼 기준 | 기록 |
| --- | --- | --- |
| 1. 도면 올리기 | 도면이 화면에 뜸(PDF는 쪽 선택 포함) | 파일 형식, 실패 시 안내 문구 |
| 2. 축척 맞추기 | 숫자 치수 하나로 축척 적용 | 고른 치수, ‘확인용 재기’ 사용 여부와 잰 값 |
| 3. 외곽 벽 따라 그리기 | 닫힘(벽 N개) | 다시 그린 횟수, 공간 안의 벽까지 그리려 했는지 |
| 4. 출입문 놓기 | 출입문이 벽 위에 놓임 | 벽 선을 못 찾아 헤맨 시간 |
| 5. 창·기둥·급배수 | 있는 것을 놓음(급배수는 직접 확인한 경우만) | 놓지 못한 것과 이유 |
| 6. 벽 길이를 도면 숫자로 맞추기 | 도면 숫자와 화면 길이가 같음 | 함께 바뀐 벽 강조를 이해했는지, 되돌리기 사용 여부 |
| 7. 면적 확인 | 계산 면적·입력 면적·차이를 읽음 | 차이 값과 고객 해석 |
| 8. 만들기 → 가구 놓기 | 편집 화면에서 가구 하나 이상 놓고 저장 | 꺾인 공간에서 빈 공간 시작을 어떻게 받아들였는지 |

공간마다 ‘도움 없이 도달한 마지막 단계’, 걸린 시간, 도면 종류(사무실·아파트·상가, 방 구획 유무)를 적습니다. 방이 나뉜 도면(아파트 등)은 외곽만 그린다는 안내를 고객이 이해했는지 따로 적습니다(공간 안의 벽·방문은 후속 범위).

## 9. 업체 제안 검증: 받은 자료만으로 제안할 수 있는가 (고객 테스트와 일부 병행)

고객 테스트에서 만든 공간(고객 동의를 받은 것)을 운영자 화면에서 ‘테스트 요청’으로 표시하고 업체 2~3곳에 같은 공간을 배정합니다. 업체에는 서비스 화면만 주고 따로 설명하지 않습니다. 질문은 서비스의 자료 요청이나 운영자에게 하게 해서 그 수와 내용을 셉니다.

병행 순서: 고객 1~2명이 공간을 만들고 요청하면 바로 업체에 배정 → 업체가 견적·설계 제안을 내는 동안 다음 고객 테스트를 진행 → 제안이 2건 이상 모인 공간으로 10장의 비교 이해 테스트.

| 무엇 | 어떻게 재나 | 기록 |
| --- | --- | --- |
| 받은 자료만으로 1차 견적을 냈는가 | 냈음 / 추가 자료를 받고 냈음 / 못 냄 | 기록장 ‘참여자별 결과 → 업체’ |
| 견적 항목을 금액으로 확정한 비율 | 금액 확정 · 현장 확인 필요 · 해당 없음 비율 | `npm run test:report` |
| 추가 질문·자료 요청 수와 내용 | 서비스 자료 요청 + 운영자에게 온 질문 | 기록장(수), 문제 기록(내용) |
| 설계 제안을 낼 수 있었나 | 고객 배치대로 / 수정 제안 / 못 냄 | 기록장, `npm run test:report` |
| 업체가 실제로 본 자료 | 치수 평면도, 3D, 실제·가정 표, 가구 목록, 첨부 도면 | 기록장 ‘본 자료’ |
| 막힌 화면 | 업체 화면에서 헤맨 곳 | 기록장 문제 기록(업체 영역) |
| 현장 방문 뒤 금액 변화 | 방문 뒤 최종 견적과 1차 견적의 차이(%) | 방문 뒤 기록장에 추가 |

`npm run test:report`는 서비스 기록에서 프로젝트별로 배정 → 참여 확정 → 제출까지 걸린 시간, 견적 항목 부류, 설계 제안 종류, 제출 횟수, 자료·방문 요청 수를 뽑습니다(고객 이름·주소·연락처는 출력하지 않음).

## 10. 고객 제안 비교 이해: 제안 차이를 이해하는가

제안이 2건 이상 도착한 공간에서 고객에게 비교 화면을 열어 주고 아래 6가지를 묻습니다. 운영자는 미리 화면에서 정답을 확인해 둡니다. 혼자 정확히 답하면 ○, 힌트 뒤나 일부만 맞으면 △, 못 하면 ×로 기록장 ‘참여자별 결과 → 제안 비교 이해’에 적습니다.

| 번호 | 질문 | 보는 것 |
| --- | --- | --- |
| C1 | 두 제안이 같은 요청 기준(r번호)인가요? | 같은 기준끼리 비교된다는 표시 |
| C2 | 합계에 들어가지 않은 항목은 무엇인가요? | ‘현장 확인 필요’·‘해당 없음’ 구분 |
| C3 | ‘최저’ 표시가 있거나 없는 이유는? | 금액 미정 항목이 있으면 최저를 붙이지 않는 규칙 |
| C4 | 두 업체의 설계 제안은 어떻게 다른가요? | 고객 배치대로 / 수정 제안 내용·첨부 |
| C5 | 한 업체만 넣은 공사 범위 항목은? | 공사 범위 비교 표 |
| C6 | 마음에 드는 업체에 현장 방문을 요청하려면? | 방문 요청 위치 |

질문별 ○ 비율이 낮은 곳의 화면을 다음 수정 목록에 올립니다(기준은 테스트 뒤 정합니다). 고객이 고른 업체와 이유도 함께 적습니다.
