# 플랫폼 기획 현황

**현재 기준(2026-10-05):** 커뮤니티·업체 직접 참여·입점 쇼핑·집 전체 평면·상품 배치가 구현돼 있습니다. AI 도면 인식과 주소별 등록 도면도 추가했습니다. 인식 좌표를 원본 벽선·문·창 틈으로 다시 측정하도록 고쳐 기존 위치·벽 연결 오류를 해결했습니다. 가상 도면 6종×2회 실제 API 검사는 모두 통과했습니다. 갈매스타힐스 공개 기본형 7타입 검색과 고객의 타입 확인·업로드 대체 흐름을 추가했습니다. 112A는 원본을 대조해 따라 그린 참고 배치로 3D·편집·업체 전달을 검증했습니다. 실제 112A의 AI 자동 인식은 성공하지 못했으며 참고 배치 검증과 구분합니다. 모든 고객 도면의 자동 인식 정확도는 미확정입니다. 실제 결제·메일·주소 API도 연동 검증 전입니다. 현재 범위는 [v2-plan.md](v2-plan.md), AI 상세는 [ai-floorplans.md](ai-floorplans.md)를 보세요.

## 이하: 초기 MVP의 기획·검증 이력

아래 완료/미개발 수치와 로드맵은 2026-10-02 당시 기록입니다. 현재 기능 완료 판정에는 사용하지 않습니다.

기준: 11차 개발 마감 · 테스트 착수 반영 (2026-10-02). 웹 페이지판과 같은 내용입니다.

전체 방향은 ‘공간 커뮤니티 + 내 공간 3D + 시공 경쟁 제안 + 입점 쇼핑’을 하나의 공간 프로젝트로 잇고, 사무실로 먼저 검증하는 것입니다. 그 가운데 **내 공간 만들기 → 가구 배치 수정 → 저장 → 원할 때 시공 제안 요청 → 같은 기준의 업체 제안 비교**는 개발을 마쳤습니다. 운영자 배정은 초기 운영 방식이고, 목표는 **비공개 경쟁입찰형 시공 매칭**입니다. 커뮤니티·주거 3D·입점 쇼핑(상품 판매 → 상품 3D 배치)은 로드맵에 두고 착수 조건을 정했습니다.

| 갈래 | 확인할 것 | 재는 것 | 기록·근거 |
| --- | --- | --- | --- |

## 값 구분: 임시 검사·알림값과 엔진 지원 범위

| 값 | 구분 | 지금 하는 일 | 바꾸는 방법 |
| --- | --- | --- | --- |
| 문 앞 여유 750mm | 임시 검사값 | 편집 검사가 문 앞 750mm 안의 가구를 알림. 화면 표시 ‘현재 임시 검사값 750mm’ | 테스트·업체 의견으로 근거가 생기면 값만 조정(코드 한 곳) |
| 급배수 거리 3,000mm | 임시 알림값 | 제안 위치의 탕비 설비가 고객 확인 급배수에서 직선 3,000mm 넘으면 거리만 알림. 연결 가능 여부는 판정하지 않음 | 업체 의견으로 근거가 생기면 값만 조정(코드 한 곳) |
| 출입문 2,500mm | 엔진 지원 범위 | 출입문이 가까운 모서리에서 2,500mm 이내일 때만 자동 배치. 벗어나면 빈 공간에서 시작. 화면 표시 ‘현재 자동 배치 지원 범위’ | 값을 바꾸는 것이 아니라 엔진 골격을 더 만들어야 넓어짐. 테스트에서 범위 밖 공간이 많으면 개발 순서를 앞당김 |

세 값의 확정은 다른 기능 개발의 일괄 선행조건이 아닙니다. 임시 검사·알림값은 근거가 생기는 대로 하나씩 조정하고, 엔진 지원 범위는 엔진 개발 순서로 다룹니다.

### 공간 탐색(사례)

사례를 보고 저장해 요청에 붙이는 입구

- **완료** 사례 탐색 메인과 필터(공간 종류·평수·스타일), 큰 공간 카드, 휴대폰 하단 메뉴
- **완료** 사례 상세: 눈높이 3D → 입체 배치도 → 치수 평면도(같은 배치 데이터), ‘3D 예시’와 ‘실제 시공 사례’ 표시
- **완료** 사례 저장과 관심 업체를 나눠 관리, 요청서에 참고 사례 연결(운영자·배정 업체 화면까지)
- **보완 필요** 실제 시공 사진: 지금 사례는 모두 3D 예시(예시라고 표시). 실제 사례와 참여 업체 자료 확보가 필요
- **보완 필요** 결정 대기: 공간 종류 기준(업종 vs 공간 단위), 포인트 색, 상세 화면 하단 메뉴, 카드에 업체명

### 내 공간 만들기

실제 구조(벽·문·창·기둥)를 입력해 3D 공간을 만드는 단계

- **완료** 치수 입력: 직사각형, 출입문 위치·폭, 벽별 창, 기둥, 급배수 위치(고객 확인), 천장 높이
- **완료** 도면 따라 그리기: 이미지·PDF 밑그림, 두 점 축척, 외곽 벽 찍기(ㄱ자 등 꺾인 공간 포함), 출입문·창·기둥·급배수, 벽 길이 맞추기(함께 바뀌는 벽 강조·되돌리기)
- **완료** 면적은 계산·입력·차이 숫자로 표시, ‘실제·자동 제안·가정·반영 제한·후속 범위’ 표
- **보완 필요** 고객 사용성 테스트 결과 반영(테스트 진행 중)
- **보완 필요** 기울어져 스캔된 도면을 바로잡는 기능 없음(반듯한 스캔을 안내)
- **후속 범위** 공간 안의 벽·방문 재현(아파트·주택의 방 구조) — 주거 3D의 선행 기능
- **후속 범위** 기울어진·곡선 벽, DWG·DXF 직접 열기
- **후속 범위** 도면 자동 인식(AI 초안 → 사용자 확인), 주소 기반 아파트 도면 검색

### 자동 배치

입력한 조건으로 출발점 배치를 만드는 엔진

- **완료** 목적별 세 골격(방문객 응대·직원 협업·집중 업무), 이유·장단점·비교 수치, 만들 수 없는 골격은 만들지 않음
- **완료** 입력한 출입문 위치 반영, 엔진이 같은 검사로 자기 배치를 걸러냄(8,080 조건에서 검사에 걸린 배치 0건)
- **보완 필요** 엔진 지원 범위: 출입문이 모서리에서 2,500mm 이내일 때만 자동 배치. 넓히려면 값이 아니라 엔진을 개발해야 함(테스트에서 범위 밖 공간 비율을 보고 결정)
- **보완 필요** 기둥을 피하지 않음(겹치면 검사로 알림)
- **보완 필요** 창은 안쪽 벽만 반영, 20~50평 직사각형만 지원. 꺾인 공간은 수동 배치로 확정

### 배치 편집

자동 배치나 빈 공간에서 가구를 직접 고치는 단계

- **완료** PC·휴대폰 편집: 이동·90° 회전·복제·삭제·추가·숫자 위치·되돌리기, 같은 데이터로 3D
- **완료** 저장할 때마다 새 버전, 이전 버전 보존, 버전 사이 바뀐 점
- **완료** 자동 검사(검사하지 않는 것 명시, ‘시공 가능’ 표현 없음), 탕비 설비 자동 제안 위치 / 고객 확인 위치
- **완료** 휴대폰: 평면 아래 가구 추가, 검사·저장 안내 접기
- **보완 필요** 임시 검사·알림값: 문 앞 750mm(임시 검사값), 급배수 3,000mm(임시 알림값, 연결 판정 아님). 근거가 모이면 값마다 따로 조정하며, 다른 개발의 선행조건이 아님
- **후속 범위** 칸막이·방 크기 편집, 15° 회전, 실제 제품 규격(지금은 개념 가구)

### 시공 제안 요청과 비교

같은 기준으로 여러 업체의 비공개 제안을 받아 비교

- **완료** 요청서: 보낼 배치 버전 선택 → 배치·치수·조건을 하나의 기준(r번호)으로 고정
- **완료** 운영자 배정(초기 운영 방식), 업체 참여 확정, 응답 기한·다시 알리기·배정 취소·재배정
- **완료** 업체 화면: 공간 이름·상세 주소·연락처 비공개(현장 방문을 요청한 업체에만 공개)
- **완료** 견적 3부류(금액 확정·현장 확인 필요·해당 없음), ‘최저’ 표시 규칙, 임시 저장, 제출 이력
- **완료** 설계 제안(고객 배치대로 / 수정 제안 + 첨부, 첨부는 그 업체와 고객만), 같은 요청 기준끼리 비교
- **완료** 요청 뒤 변경: ‘변경 내용 보내기’로 같은 업체에 새 기준(r2), 이전 기준 제안은 섞지 않음
- **완료** 현장 방문 요청, 운영자의 계약 기록
- **보완 필요** 업체가 받은 자료로 제안할 수 있는지, 고객이 제안 차이를 이해하는지는 이번 테스트에서 검증(업체는 고객 테스트와 일부 병행)
- **보완 필요** 고객이 화면에서 직접 ‘이 업체로 진행’을 고르는 단계 없음(지금은 방문 요청 + 운영자 계약 기록)
- **미개발** 계약 이후 진행(시공 일정·완료 확인) → 시공 후기 연결
- **미개발** 목표: 비공개 경쟁입찰형 시공 매칭 — 승인된 업체가 고객 요청에 직접 참여해 가격·설계·자재·기간을 제안하고 고객이 비교해 선택(아래 로드맵)
- **후속 범위** 업체가 편집기로 직접 그리는 수정안

### 알림·계정·운영자

가입부터 운영자 관리까지

- **완료** 서비스 알림함, 메일 발송 구조(발송 계정이 없으면 기록만), 운영자 메일 기록 화면

- **완료** 운영자 화면: 배정, 업체 직접 등록, 사례 대신 관리, 테스트 요청 표시, 자료 요청
- **완료** 테스트 결과 요약 스크립트(업체 제출·견적 항목 부류·설계 제안·소요 시간)와 공용 테스트 기록장(CSV 내보내기)

## 시공 경쟁 제안 로드맵: 운영자 배정에서 업체 참여 신청으로

운영자 배정은 초기 운영 방식입니다.

**목표** · 비공개 경쟁입찰형 시공 매칭: 고객이 공사 조건을 등록하면 승인된 업체들이 참여해 가격·설계·자재·기간을 제안하고, 고객이 비교해 선택합니다. 업체는 다른 업체의 금액과 제안을 볼 수 없고, 최저가 자동 낙찰은 하지 않습니다.

| 단계 | 방식 | 내용 |
| --- | --- | --- |
| 1단계 · 지금 | 운영자 배정 | 운영자가 요청을 검토하고 업체를 골라 배정. 업체는 참여 여부를 답하고(참여 검토 중 → 작성 중) 같은 요청 기준으로 비공개 제안 |
| 2단계 | 운영자 배정 + 업체 참여 신청 | 승인된 업체가 조건에 맞는 요청 목록(공간 이름·상세 주소·연락처 비공개)을 보고 참여를 신청 → 운영자가 확정. 운영자 배정도 계속 씀 |
| 3단계 · 목표 | 비공개 경쟁입찰형 시공 매칭 | 승인된 업체가 고객 요청에 직접 참여하고, 요청마다 정한 참여 상한 안에서 참여가 확정됨(확정 방식은 선착순인지 조건에 따른 선정인지 정책 결정 대기). 업체끼리 금액·제안을 볼 수 없는 상태로 가격·설계·자재·기간을 제안 → 고객이 같은 기준으로 비교해 선택(최저가 자동 낙찰 없음). 운영자는 업체 자격과 이상 행동을 관리 |

참여 업체 수는 상한:

- 참여 업체 수는 상한입니다. 상한을 다 채우지 않아도 요청은 진행합니다.
- 고객 화면에 지금 참여한 업체 수(상한 대비)와 도착한 제안 수를 보여 줍니다.
- 업체가 부족하면 고객이 먼저 도착한 제안을 확인하거나, 더 기다리기(참여 기간 연장)를 고를 수 있게 합니다.
- 운영자에게 상한 미달 요청을 따로 보여 주고, 2단계에서는 운영자가 업체를 더 배정할 수 있게 합니다.

2단계 착수 조건:

1. 업체 제안 검증(이번 테스트 갈래 2)에서 업체가 받은 자료만으로 제안할 수 있음을 확인
2. 고객 제안 비교 이해(갈래 3)에서 고객이 제안 차이를 이해함을 확인
3. 요청당 상한을 채울 만큼의 승인 업체(지역·공사 범위별)
4. 정책 결정: 요청당 참여 상한, 상한 미달일 때 고객 안내·대기 기간, 업체 자격, 참여 비용·수수료 여부
5. 알림 실제 발송(메일) 연결 — 새 요청·신청 결과를 업체가 제때 받아야 함

지금 있는 기반을 그대로 씁니다: 업체 승인 상태, 참여 확정 단계, 응답 기한·배정 취소, 같은 요청 기준 비교, 업체 화면의 비공개 범위. 지금 제안에도 가격(항목별 금액), 설계(설계 제안), 자재(항목별 사양), 기간(공사 기간)이 이미 들어 있습니다.
