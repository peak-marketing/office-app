# 주거 1차 개발 범위: 집 상담 신청과 방 한 칸 가구 배치

작성: 2026-10-02. 같은 날 개정: 600mm는 편집 참고 알림, 고정 구조물·크기 조절 검사 반영, 방 5개 독립 관리, 주거 자동 배치는 후속 검토. 웹 페이지판과 같은 내용입니다. 정해지지 않은 값은 기본값으로 정했고, 테스트 뒤 조정할 수 있는 임시값입니다.

## 기준

1. **주거 신청**: 원룸·오피스텔·빌라·아파트를 받습니다. 주거용 입력·공사 범위·견적 항목을 사무실과 구분하고, 도면이나 치수가 없어도 상담을 신청할 수 있습니다.
2. **1차 주거 3D**: ‘치수를 아는 방 한 칸의 가구 배치’로 한정합니다. 욕실·고정 설비를 뺀 공간을 집 전체의 정확한 3D로 안내하지 않습니다.
3. **집 전체 3D의 다음 개발**: 내부 벽·방문·방 구분입니다. 아파트 도면 템플릿과 주소 검색은 선행조건이 아닙니다.
4. **개발 방식**: 사무실 테스트 버전은 보존하고 별도 개발 환경에서 진행합니다. 커뮤니티·쇼핑은 이번에 구현하지 않습니다.

## 이번에 만드는 것

- **집 상담 신청**: 주거 유형·지역·공사 범위만 있으면 신청됩니다. 면적·도면·사진·방 배치는 모두 선택입니다.
- **주거 제안·비교**: 주거 견적 14항목으로 받습니다. 비공개 제안, 같은 요청 기준끼리 비교, 변경 내용 보내기는 사무실과 같습니다.
- **방 한 칸 가구 배치**: 치수를 아는 방 하나에 문·창·고정 구조물을 넣고 개념 가구를 직접 놓아 3D로 봅니다. 방마다 독립된 참고 배치이며, 화면마다 ‘방 한 칸 · 집 전체 아님’을 표시합니다.
- **업체 분야·배정**: 업체 분야에 ‘주거’를 더하고, 운영자 배정 화면에서 주거 요청이면 주거 분야 업체를 먼저 보여 줍니다.
- **공간 탐색 예시**: 사무실/집 필터와 주거 유형 필터, 방 한 칸 3D 예시를 더합니다. 예시는 ‘3D 예시 · 방 한 칸’으로 표시합니다.

## 방 한 칸 가구 배치(1차 주거 3D)

- 직사각형 방 한 칸: 가로·세로(임시 지원 범위 1.5~15m), 천장 높이(선택)
- 방문 1개, 다른 문 자리 최대 3개(욕실·발코니·현관 문 등), 창 위치·폭(모르면 ‘위치 모름’으로 두고 임의로 넣지 않음)
- 고정 구조물: 기둥·붙박이장·싱크대 자리처럼 크기(가로·깊이·높이)만 있는 상자. 가구와 겹치면 검사에서 알림
- 치수 검토용 개념 가구 20종(실제 상품 아님)과 크기 조절(가로·깊이 300~3,000mm, 높이는 고정). 바꾼 크기는 평면·3D·검사·저장 후 복원에 같은 값으로 쓰임
- 확인할 것 4종: 가구끼리 겹침, 고정 구조물과 겹침, 방 밖, 문 앞 장애물(방문·다른 문 자리 앞 바닥: 문 폭 × 깊이 문 폭, 최대 900mm)
- 통로 간격 알림(편집 참고 · 임시값 600mm, 판정 아님): 마주 보는 두 면 — 가구와 가구, 가구와 벽, 가구와 고정 구조물 — 사이 빈 간격이 50mm 초과 600mm 미만이고 300mm 이상 마주 볼 때 알림. ‘안전한 통로’·‘시공 가능’처럼 판정하지 않음
- 방마다 독립된 참고 배치(이름·치수·가구·배치 버전을 방별로 관리), 한 요청에 최대 5개. 여러 개를 만들어도 서로 잇지 않고 집 전체 도면으로 표시하지 않음
- 요청을 보낼 때 방별 배치 버전을 요청 기록에 함께 보관. 보낸 뒤 방 추가·삭제·수정은 ‘변경 내용 보내기’를 눌러야 업체 기준에 반영

## 다음 핵심 개발: 내부 벽·방문·방 구분

- 도면 따라 그리기에 내부 벽선과 방문을 더합니다.
- 벽으로 나뉜 영역을 방으로 구분하고 방 이름·면적을 붙입니다.
- 방 한 칸 배치를 집 안의 방으로 연결해 집 전체 평면과 3D를 만듭니다. 욕실·주방 설비는 자리 표시부터 시작합니다.
- 같은 기능을 사무실의 기존 구조(회의실 벽·문) 재현에도 씁니다.
- 아파트 평형 템플릿과 주소 검색은 이 개발의 선행조건이 아니며, 필요하면 그 뒤에 더합니다.

## 완료 기준


### 보존

1. 사무실 테스트 서버(3100)의 데이터·업로드·소스가 작업 전후로 같음(DB 덤프·업로드·소스 사본 해시 비교)
2. 개발 사본에서 기존 사무실 검사 전체 통과(단위 검사, 자동 배치 조건 검사, 브라우저 검사 10묶음)
3. 기존 테스트 데이터 사본을 개발 사본에서 열면 기존 프로젝트·제안·요청 기록이 그대로 보이고 ‘사무실’로 표시됨

### 주거 신청

4. 4개 유형 각각: 도면·치수 없이 유형·지역·공사 범위만으로 신청 → 운영자 화면에 ‘집 · 유형’으로 표시
5. 사진만, 도면 첨부, 방 배치 첨부, 자료 없음 네 경우 모두 신청 가능
6. 입력하지 않은 항목은 고객·공유·인쇄·업체·운영자 요약 모두에서 ‘입력하지 않음’으로 표시하고 추정값을 채우지 않음
7. 휴대폰(390px)에서 신청 전 과정을 가로 스크롤 없이 진행

### 업체·제안·비교

8. 업체 분야(사무실·주거) 저장, 배정 화면에 분야 표시, 주거 요청에서 주거 분야 업체가 먼저 보임
9. 업체 요청 화면에 집 요약·공사 범위·자료·방 배치(참고 문구)가 보이고, 상세 주소 공개 규칙은 지금과 같음
10. 주거 14항목 견적을 PC·휴대폰에서 작성·임시 저장·재접속·제출, 미정 금액을 0원으로 계산하지 않음
11. 고객 비교는 같은 요청 기준끼리 14항목으로 비교하고, ‘최저’ 표시·변경 내용 보내기(r2)는 사무실과 같음
12. 사무실 요청은 사무실 13항목 그대로이고 두 항목 세트가 섞이지 않음

### 방 한 칸 가구 배치

13. 방 치수 → 문·창·고정 구조물 → 개념 가구 놓기·크기 조절 → 저장 → 3D 확인이 PC·휴대폰에서 끝까지 됨
14. 확인할 것 4종(가구끼리·고정 구조물과 겹침, 방 밖, 문 앞 장애물)과 통로 간격 알림이 따로 보이고, 알림은 무엇과 무엇 사이 몇 mm인지 적으며 판정하지 않음
15. 가구 크기를 바꾸면 평면·3D·겹침 검사·저장 후 다시 열기에 같은 크기가 쓰임
16. 방 한 칸 3D가 나오는 모든 화면(편집·프로젝트·업체·공유·인쇄)에 ‘방 한 칸 · 집 전체 아님’ 표시, 쓰지 않는 표현이 없음(문구 자동 검사)
17. 방 5개는 각각 독립된 참고 배치, 요청을 보낼 때 방별 배치 버전이 함께 보관되고, 보낸 뒤 추가·삭제·수정은 ‘변경 내용 보내기’ 전까지 업체 기준에 반영되지 않음

### 공간 탐색·범위

18. 사무실/집 필터와 주거 유형 필터, 방 한 칸 3D 예시 4건 이상이 모두 ‘3D 예시 · 방 한 칸’으로 표시, 사무실 사례 14건은 그대로
19. 커뮤니티·쇼핑·집 전체 3D·템플릿·주소 검색 화면이 생기지 않음

## 진행 순서

1. **개발 환경**: 사본·포트·데이터·변경 기록을 만들고, 사본에서 기존 검사 전체가 통과하는지 먼저 확인
2. **주거 신청**: 공간 종류(사무실/집) 구분, 집 상담 신청 화면, 집 요약(고객·인쇄·공유·운영자)
3. **업체·제안·비교**: 업체 분야와 배정, 업체 요청 화면, 주거 견적서 14항목, 고객 비교
4. **방 한 칸 가구 배치**: 방 만들기, 주거 가구·크기 조절, 검사 4종, 표시 문구, 요청 연결
5. **공간 탐색 예시**: 공간 종류·주거 유형 필터, 방 한 칸 3D 예시
6. **검증**: 완료 기준 전체, 사무실 회귀, 기존 데이터 사본, 결과 보고(화면 포함)

## 구현 메모

- 프로젝트에 공간 종류(사무실/집) 칸을 더하고, 기존 프로젝트는 모두 ‘사무실’로 둡니다.
- 집 정보는 버전 입력에 함께 저장해 요청 기록(r1·r2) 구조를 그대로 씁니다.
- 방 배치는 버전에 방 목록으로 저장합니다. 고치면 새 버전이 생기고, 보낸 뒤라면 변경 내용 보내기로 전달합니다.
- 견적 항목 세트는 공간 종류로 고릅니다(사무실 13·주거 14). 비교는 같은 세트끼리만 합니다.
- 업체에 분야 칸을 더하고, 기존 업체는 ‘사무실’로 둡니다.
