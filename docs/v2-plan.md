# 2차 통합 개발 설계 (2026-10-05~)

목표: 공간 탐색·공유·쇼핑(오늘의집과 비슷한 경험)에 내 공간 3D와 시공사 비공개 경쟁입찰을 결합한다. ‘내 공간’ 프로젝트로 이어 주되, 탐색·공간 만들기·시공 요청·공유·쇼핑은 각각 따로 쓸 수 있어야 한다.

- 개발 위치: `platform-next`(platform-home 사본, git). 3100(`platform`)과 그 데이터는 건드리지 않는다. 시작 전 3100 백업 `platform/data/backups/2026-10-05-18-18-25-before-v2-dev`, 이전 검사용 사본 `dev-data/live-copy-20261005`.
- 확인용 서버 3300(개발 데이터), 자동 검사 3301(`npm run test:e2e`, 묶음마다 새 데이터). 검사 코드는 `tests/e2e/`.

## 역할과 계정

- 고객(customer), 파트너(vendor), 운영자(admin). 파트너 한 계정이 시공(vendors)과 판매(sellers)를 함께 가질 수 있다. users.role의 'vendor'를 ‘파트너’로 쓴다(표 구조를 바꾸지 않는다).
- 판매만 하는 파트너도 있다(vendors 행 없이 sellers 행만).

## 화면 구조

- 고객 아래 탭(휴대폰): 홈 · 커뮤니티 · 쇼핑 · 내 공간 · 마이. 위 머리: 로고, 검색, 장바구니, 알림, 계정.
- 홈 `/`: 오늘의 공간(커뮤니티 사진), 인기 상품, 시공 사례, 내 공간·시공 요청 시작.
- 커뮤니티 `/community`(공간 소개·시공 후기), `/community/[id]`, `/community/new`.
- 쇼핑 `/shop`, `/shop/search`, `/shop/products/[id]`, `/cart`, `/checkout`, `/orders`, `/orders/[no]`, 테스트 결제 `/pay/test/[no]`.
- 시공: `/cases`(업체 사례), `/vendors`, 내 공간 `/projects`, 시공 요청.
- 마이 `/me`: 내 글, 주문, 스크랩(공간·사례·상품·업체), 내 공간.
- 파트너: `/partners`(입점 안내·신청), 시공 `/vendor`·`/vendor/open`(공개 요청 참여)·`/vendor/profile`, 판매 `/seller`(상품·주문·취소/반품·정산).
- 운영자: 요청·업체(기존) + `/admin/sellers`, `/admin/products`, `/admin/orders`, `/admin/settlements`, `/admin/community`.

## 정책(기본값, 테스트 뒤 조정)

- 경쟁입찰: 요청마다 참여 방식(운영자 배정만 / 업체 직접 참여 + 운영자 배정)과 참여 상한(기본 5곳). 직접 참여는 상한 안에서 선착순. 업체끼리 제안 비공개, 최저가 자동 낙찰 없음, 같은 요청 기준끼리 비교. 상세 주소·연락처는 방문 요청한 업체에만.
- 커뮤니티: 공간 소개(누구나), 시공 후기(계약 결과가 기록된 고객만, 그 시공사와 연결되면 ‘계약 확인’ 표시), 업체 사례(업체가 올린 것, 기존 vendor_cases)는 서로 구분해 표시. 신고는 운영자가 처리(가리기·삭제·기각).
- 쇼핑: 판매자 신청→운영자 승인→상품 등록(옵션 조합별 재고·가격). 주문은 판매자별 묶음 배송비. 상태: 결제 대기→결제 완료→배송 준비→배송 중→배송 완료→구매 확정(배송 완료 7일 뒤 자동). 취소(발송 전, 전액 환불, 재고 복구), 반품(배송 완료 뒤, 단순 변심이면 반품 배송비 차감). 정산: 구매 확정 금액 − 수수료(기본 10%, 판매자별 조정) − 반영된 환불, 운영자가 확정·지급 처리(실제 이체는 수동).
- 상품 3D: 규격(가로·깊이·높이 mm)이 있는 상품은 실제 크기 상자로, 3D 모델(glTF/GLB)이 있으면 모델로 내 공간에 놓는다. 놓은 상품은 상세·장바구니로 이어진다. 모델이 없는 상품도 사진으로 판매.
- 집 전체: 바깥 벽(치수·도면 따라 그리기) + 내부 벽·방문 + 방 구분(벽으로 나뉜 영역에 이름). 방 한 칸 참고 배치(1차)는 그대로 둔다.
- 주소로 도면: 주소 검색(도로명주소 API)과 건축물대장(공공데이터포털)으로 면적·사용승인일만 채운다. 공공 API로 받을 수 없는 평면도는 건축물현황도(정부24)·관리사무소·분양 자료로 받도록 안내하고, 올리면 따라 그리기로 이어 준다.

## 집 전체 평면(2026-10-05, platform-house에서 개발)

고객이 도면 이미지나 실측 치수로 집 전체 평면을 직접 만들고, 내부 벽·방문·창·방 구분과 개념 가구 배치를 저장한다. 주소별 등록 도면 선택과 AI 인식 흐름도 추가했다. 등록 도면 데이터와 AI 키 없이 자동 인식을 가장하지 않는다.

- 데이터: 집 요청 버전의 `versions.house`(JSON, 이전 버전은 NULL). 좌표는 미터, RoomModel과 같은 규칙(x 왼쪽→오른쪽, y 앞→안쪽). 바깥 윤곽(반시계 직각 다각형, 바깥 벽 안쪽 면) · 천장 높이(기본 2,400mm) · 내부 벽(가로·세로 선분, 두께 기본 100mm, 바깥 벽은 200mm로 그림) · 문·통로·창(벽 id와 벽 시작점에서의 거리·폭, 여닫이는 경첩 쪽·여는 쪽) · 방 이름(그 방 안의 점) · 고정 구조물 자리 · 가구 · 밑그림 · 평면 번호(rev). 코드: `lib/space/house*.ts`.
- 방 구분: 윤곽 안을 50mm 격자로 나눠 벽이 지나는 칸을 막고 이어진 칸끼리 묶는다(같은 입력이면 같은 결과). 문·통로는 방을 잇는 자리라 방을 나누지 않는다. 벽 끝이 닿지 않으면 두 방이 하나로 잡히고 ‘닫히지 않은 벽’ 경고가 뜬다. 폭 300mm 이하 또는 0.25㎡ 미만 영역은 방이 아닌 ‘벽 사이 틈’, 1㎡ 미만 방은 확인 권고. 방 면적은 벽 안쪽을 격자로 센 추정값(㎡·평)이며 실측·공부상 면적이 아니라고 적는다.
- 만들기: 치수(가로·세로 2,000~40,000mm, 임시 범위) 또는 도면 이미지(JPG·PNG·WEBP)에서 길이를 아는 두 점으로 축척을 맞추고 바깥 벽 모서리를 따라 찍기. 수동 입력 경로다. 별도 `/spaces/recognize`는 AI로 바깥·내부 벽과 문·창·방 이름을 읽고 실제 가로를 확인한다.
- 편집: 벽 그리기(누르기 두 번 또는 숫자, 50mm 격자·벽 끝·벽 선·바깥 벽에 맞춤) / 문·통로(방문·욕실 문·현관문·발코니 문·미닫이·통로) / 창(바깥 벽만) / 방 이름(거실·침실N·주방·욕실·현관·발코니·드레스룸·다용도실·기타·직접 입력) / 고정 구조물(기둥·붙박이장·싱크대 자리·욕조·샤워 자리·변기 자리·세면대 자리·보일러실·신발장, 자리 표시) / 가구(주거 개념 가구 20종·크기 조절, ‘치수 검토용 개념 가구 · 실제 상품 아님’). 되돌리기, 확대, 휴대폰은 누르기·고른 것 다시 눌러 끌기·화살표. 3D는 기존 3D 화면으로 그린다(문 자리는 벽을 비우고 문 위 벽만, 방마다 바닥 색).
- 검사(서버·화면 같은 함수): 가구끼리 겹침, 고정 구조물과 겹침, 벽에 걸침(내부 벽, 문·통로 자리는 제외), 집 밖, 문·통로 앞 장애물(문 폭 × 깊이 문 폭·최대 900mm, 내부 벽은 양쪽·바깥 벽 문은 안쪽), 방 밖(가구 중심이 벽 위). 통로 간격 알림은 1차와 같은 정의(마주 보는 두 면 50mm 초과 600mm 미만, 300mm 이상 마주 봄, 가구·벽·고정 구조물)이며 판정이 아닌 편집 참고. 저장을 막는 오류: 벽이 바깥 벽 밖·바깥 벽 위·같은 선에 겹침·기울어짐, 문·창이 벽 밖·서로 겹침·창과 현관문은 바깥 벽만, 고정 구조물이 집 밖, 천장 높이 범위.
- 요청: 요청 기록(r번호)에 평면을 통째로 넣고, 바뀐 점(평면 번호, 내부 벽 수, 문·통로·창, 방 수·이름·면적, 고정 구조물, 가구)을 업체 문장으로 만든다. 보낸 뒤 고친 평면은 ‘변경 내용 보내기’ 전까지 업체에 보이지 않는다. 공사 요청 없이도 만들고 저장할 수 있다(프로젝트는 요청 전 그대로).
- 화면: 고객 프로젝트 탭 ‘집 전체 평면’(`/projects/[id]/house`), 만들기 `/projects/[id]/house/new`, 편집 `/projects/[id]/house/edit`, 업체 요청 상세(받은 요청 기록의 평면만), 운영자 프로젝트 상세, 공유 링크, 인쇄·PDF. 모든 화면에 ‘고객이 입력한 집 평면 · 실측 도면 아님 · 설비·구조는 표시한 것만’.
- 방 한 칸 배치(1차)는 그대로 두고 따로 관리한다. 집 정보·방 배치를 저장해도 평면은 이어 가고, 평면을 저장해도 방 배치는 그대로다.
- 하지 않는 것: 사선·곡선 벽, 층이 여러 개인 집, 설비 연결·구조벽·법규 판정, 집 자동 배치(후속 검토). 실제 상품 배치는 아래 ‘실제 상품 3D 배치’로 구현했다.
- 검사: `npx tsx scripts/check-house.ts`(방 찾기·검사·맞춤 규칙), 브라우저 `npm run test:e2e -- house`.

### 하지 않은 것·후속

- 상품 구매 후기(별점), 쿠폰·포인트, 묶음 상품, 상품 문의(Q&A), 판매자별 배송비 상품 단위 설정, 품절 알림.
- 결제: 가상계좌·계좌이체(웹훅 필요), 에스크로, 현금영수증, 부분 결제. 토스 결제 승인·부분 취소 코드는 있으나 키로 확인하기 전.
- 정산 지급 자동화(지급대행), 세금계산서 발행.
- 커뮤니티: 팔로우, 집들이 형식(목차·여러 문단), 동영상, 해시태그.
- 집 전체 평면: 사선·곡선 벽, 여러 층, 바깥 윤곽 고치기(지우고 다시 만들기). 집 자동 배치(후속 검토).
- 주소: 평면도 자동 확보(공공 API 없음). 아파트 등록 도면의 운영자 등록·주소/단지명 검색·타입 선택·복사는 구현했고 실제 도면 확보는 운영에서 한다.
- 서비스 이름: 지금 ‘오피스매칭’ 그대로(`components/ui.tsx` BRAND, 메일은 BRAND_NAME). 정해 주시면 바꾼다.
