## 사무실 최신 버전과의 차이

- **기준**: 3100의 지금 코드 = 주거 1차 사본을 만든 기준 버전. 다른 점은 테스트 빌드 폴더를 빼는 .gitignore 두 줄뿐이라 합칠 때 충돌이 없습니다.
- **코드**: 추가 25(집 신청·방 배치 화면과 규칙, 주거 준비 명령, 집 예시 이미지 10장, 문서) · 수정 51(프로젝트·업체·운영자·탐색 화면의 집 분기, 견적 항목 세트, 요청 기록, 시드) · 삭제 0. package.json은 검사·준비 명령 두 줄만 추가, 의존 패키지 변화 없음.
- **데이터 구조**: projects.kind(기본 office) · vendors.fields(기본 office) · versions.rooms(빈 값) 칸 3개 추가. 표 삭제·이름 변경 없음. 서버가 데이터를 처음 열 때 자동으로 붙습니다.
- **데이터 내용**: 기존 행은 바꾸지 않습니다. 선택 단계인 주거 준비(npm run data:home-setup)가 집 예시 5건(사례 5 · 사진 10장)을 더하고 예시 업체 2곳(모아공간·라인앤폼)에 ‘주거’ 분야를 더합니다. 실제 업체·실제 요청은 건드리지 않습니다.
- **통합 중 고친 것**: 기존 데이터에는 시드가 다시 돌지 않아 집 예시가 생기지 않으므로 주거 준비 명령을 만들었습니다(여러 번 실행해도 같음, 실행 전 백업). 화면 비교에서 운영자 배정 화면의 업체 분야가 ‘사무실·집’, 업체 관리는 ‘사무실·주거’로 달라 ‘주거’로 맞췄습니다. README·현황 문서의 주거 항목도 고쳤습니다.

## 반영 절차(요약, 전체는 platform-home/docs/home-integration.md)

1. 사전 확인: 사본 커밋 6d2486d, 3100 상태, 대면 테스트가 없는 시간
2. npm run data:backup -- before-home-integration (백업 이름 기록, data:verify로 점검)
3. npm run serve:stop
4. 이전 코드 보관: platform → platform-before-home (빌드 포함, 데이터 제외, APFS 복제)
5. 코드 반영: rsync(데이터·node_modules·빌드·.env 제외), 미리보기로 지울 파일 0 확인
6. npm run build
7. npm run data:home-setup -- --dry-run → --yes (자체 백업 후 집 예시·예시 업체 분야)
8. npm run serve:start → /health 200 → 고객·운영자·업체·탐색 5분 확인

## 되돌리기

- **집 요청 0건**: R1 코드만 되돌리기: 중지 → platform-before-home에서 코드·빌드 되돌리기 → 시작. 데이터는 그대로 두어도 이전 코드가 정상 동작(B0·B).
- **집 요청이 생긴 뒤**: R2 코드 + 데이터: 중지 → 코드·빌드 되돌리기 → npm run data:restore -- <before-home-integration> --yes → 시작. 반영 뒤 데이터는 화면에서 사라지지만 before-restore 백업에 남음(A4).
- **확인 명령**: sqlite3 -readonly platform/data/app.db "select count(*) from projects where kind='home'"

## 알아 둘 점

- 중단 시간은 리허설에서 중지부터 시작까지 1분 안팎이었습니다(빌드 포함). 대면 테스트가 없는 시간에 반영합니다.
- 반영하면 공간 탐색이 최근 등록순이라 집 예시 5건이 사무실 예시보다 앞에 보이고, 모아공간·라인앤폼의 사례 수가 늘어 보입니다. 주거 준비 단계를 건너뛰면 둘 다 생기지 않습니다(집 상담 신청은 그대로 가능).
- R2로 되돌리면 반영 뒤 들어온 요청·제안이 화면에서 빠집니다(백업에는 남음). 반영 직후 확인 시간에 문제를 찾는 것이 중요합니다.
- 3100·platform·platform/data는 이번 검증에서 손대지 않았습니다(작업 전후 지문 같음, 원본 데이터 폴더에 새 백업도 만들지 않음).
