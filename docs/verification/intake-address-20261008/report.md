# 신청 화면에 주소 조회 연결 — 2026-10-08

별도 주소 조회 페이지에만 있던 기능을 고객의 실제 신청 첫 단계에 연결했습니다.

## 변경한 화면

- `/projects/new`: 보여주신 ‘자료로 상담 요청하기’ 화면. 집·사무실 선택과 주소 조회가 첫 단계에 보입니다.
- `/homes/new`: 집 유형을 고객이 고르고, 주소·동·호 조회 결과를 같은 신청서에 불러옵니다.
- `/spaces/new`: 사무실 3D 공간 만들기 첫 단계에도 주소 조회가 있습니다. 조회 면적은 참고 면적으로 쓰고, 실제 가로·세로는 직접 입력해야 합니다.

주소 검색과 동·호 선택만으로 신청을 제출하거나 기존 입력을 덮어쓰지 않습니다. ‘신청서에 불러오기’를 누르면 지역·상세주소·확인된 전용면적이 반영됩니다. 집은 ㎡·전용 기준을 유지하고, 사무실 상담은 기존 평수 입력 단위로 환산합니다. 면적을 못 찾으면 예시나 0㎡로 채우지 않습니다. 고객이 선택한 집 유형, 방 수, 욕실 수, 벽·방 모양을 주소나 면적만으로 추측하지 않습니다.

불러온 동·호 포함 상세 주소는 신청서를 저장할 때 비공개 요청 정보로 보관합니다. 업체 미리보기에는 동·호를 노출하지 않고, 현장 방문 요청 업체에게만 공개하는 기존 규칙을 유지합니다. API 조회 기록에는 동·호와 키를 남기지 않습니다. 해당 데이터 사용 안내도 화면·개인정보 페이지에 맞췄습니다.

## 실제 API와 브라우저 확인

갈매스타힐스 → 401동 → 1층 → 102호 → 전용면적 **74.94㎡** 조회를 신청 화면 안에서 확인했습니다.

| 검사 | 결과 |
| --- | --- |
| 실제 신청 흐름: 사무실 상담·공간 만들기·집 상담, PC·390px 휴대폰 | 41/41 |
| 기존 주거 흐름 | 115/115 |
| 기존 사무실 접수·운영 흐름 | 57/57 |
| 기존 플랫폼 흐름 | 69/69 |
| TypeScript·변경 파일 ESLint·운영용 빌드 | 통과 |

검사에는 검색 입력의 Enter가 다음 단계·제출을 실행하지 않는 것, 검색 폼을 중첩하지 않는 것, 불러온 값을 수정할 수 있는 것, 단계 이동·저장 뒤 면적과 주소가 남는 것, 미확인 면적과 실측 치수를 임의로 채우지 않는 것, 업체에게 동·호를 숨기는 것을 포함합니다. 실제 API 검사는 격리된 시연 DB와 포트 3344에서, 회귀 검사는 다른 DB와 포트 3345에서 실행했습니다. 실제 고객 데이터와 기존 3100 버전은 변경하지 않았습니다.

## 직접 확인

- 수정된 신청 첫 화면: http://localhost:3344/projects/new
- 집 상담 신청: http://localhost:3344/homes/new
- 고객: customer@demo.kr / demo1234

주소 조회 → 동·호 선택 → ‘건물 정보 보기’ → ‘신청서에 불러오기’ 순서입니다. 주소 조회는 선택 기능이므로 자료·치수를 직접 넣는 기존 경로도 사용할 수 있습니다. 현재 신청 유형은 집·사무실이며, 다른 용도의 공사 신청까지 새로 지원한 작업은 아닙니다.

검사 코드: `platform-next/tests/live/intake.cjs`. 원본 출력은 이 폴더의 `*.out`, 실제 화면은 `screenshots/`에 있습니다.
