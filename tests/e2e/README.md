# 브라우저 자동 검사(E2E)

실제 3100 서버·데이터에는 절대 돌리지 않는다. 실행기가 묶음마다 새 데이터 폴더(`.e2e-data/data-<묶음>`)와 격리 서버(기본 3301)를 띄운다.

```sh
npm run test:e2e                  # tests/e2e/*.cjs 전부(17묶음, 약 10분)
npm run test:e2e -- home shop     # 이름에 맞는 묶음만(예: -- office 는 사무실 묶음 전부)
E2E_BUILD=1 npm run test:e2e      # 코드를 바꿨으면 검사용 빌드(.next-test)를 새로 만든다
E2E_PORT=3302 npm run test:e2e    # 포트 바꾸기
E2E_BASE=<데이터 폴더> npm run test:e2e   # 그 데이터의 사본으로 시작(예: 운영 백업 사본). 원본은 건드리지 않는다
SHOTS=1 npm run test:e2e -- home  # 화면 캡처를 .e2e-data/shots/<묶음>/ 에 남긴다
```

- 필요: Google Chrome(`/Applications/Google Chrome.app`), `sqlite3` 명령, `npm install`(playwright-core 포함).
- 결과: `.e2e-data/summary.txt`(묶음별 통과·실패), `.e2e-data/<묶음>.out`(항목별 PASS/FAIL).
- 검사 파일 규칙: `tests/e2e/<묶음>.cjs`. 환경 변수 `B`(서버 주소)·`DB`(그 서버의 app.db)·`P`(저장소 경로)를 받고(없으면 멈춤), 항목마다 `PASS …`/`FAIL …` 한 줄씩 출력한다. 시연 계정(`*@demo.kr` / `demo1234`)과 시연 데이터가 들어 있는 새 데이터에서 시작한다고 가정한다.
- 사무실 묶음(`lib/harness.cjs` 사용)은 기대값을 고정 숫자 대신 DB에서 읽는다(예시 사례 수, 필터 결과 수, 업체 사례 수). 메일·알림·요약은 이 검사가 만든 계정·프로젝트·메일만 보고(메일은 시작할 때의 마지막 번호보다 큰 것만), 전체 건수는 검사 전 값과의 차이로 비교한다. 공통 항목 ‘서버 로그 오류 없음’도 지금 서버가 뜬 뒤의 기록만 본다. 그래서 `E2E_BASE`로 기존 데이터 사본에서 돌려도 다른 기록 때문에 어긋나지 않는다(사무실 묶음 10개는 쓰던 데이터 사본에서도 통과 확인). `home`은 아직 도우미를 쓰지 않는 따로 된 파일이다.
- 서버 처리 결과는 고정 시간 대기 대신 조건이 맞을 때까지 기다린다(`until`, 페이지 이동·`load` 이벤트, 선택자).

## 파일

| 위치 | 내용 |
| --- | --- |
| `<묶음>.cjs` | 실행기가 돌리는 묶음(맨 위 폴더의 `.cjs`만 묶음이다) |
| `lib/harness.cjs` | 공용 도우미: 환경 변수 확인, `check`/`group`, 브라우저·로그인·휴대폰 창, `sql`, `until`, `mailMark`, 화면 캡처(`SHOTS=1`), 끝에 공통 항목 ‘페이지 오류 없음’·‘서버 로그 오류 없음’. `suite(이름, { webgl: false })`면 소프트웨어 WebGL 없이 띄운다(3D를 보지 않는 묶음, 훨씬 빠름) |
| `lib/office.cjs` | 사무실 흐름 도우미(예전 `t8.cjs`): 공간 만들기·시공 제안 요청·설계 제안·견적 13항목 키·배정 번호 |
| `fixtures/` | 올리는 파일: `photo1.jpg`·`plan1.jpg`(시드 사진 사본), `trace-L.png`·`trace-R.png`·`trace-L.pdf`(따라 그리기 도면, `make-trace-fixtures.cjs`로 다시 만듦), `test-L-drawing.png`(사용성 테스트 도면) |
| `legacy/` | 사무실 회귀 묶음의 복원본(2026-10-02 원본 그대로, 실행기는 돌리지 않음). 실행하는 쪽은 맨 위의 `office-*.cjs`. 출처·예전 이름과의 대응은 `legacy/PROVENANCE.md` |

`floorplan.cjs`는 이미지·PDF 로드와 고정 인식 기록에서 3D/저장/업체 전달을 검증합니다. 실제 AI 모델 호출·인식 정확도 검사가 아닙니다. 단위 검사는 `npm run check:floorplan`이며 API 응답은 모의 응답입니다. 기존 서버 빌드에 영향을 주지 않으려면 `E2E_DIST=.next-ai E2E_BUILD=1 npm run test:e2e -- floorplan`을 사용합니다.
